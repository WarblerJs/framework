# Final Release Audit

Status: Release Candidate publication review

Verdict: BLOCKED

## Executive Summary

WarblerJS has an operational engineering release gate and RC metadata for the publishable foundation packages. All package-local typechecks and tests pass through the repository package gate, and Playground passes unified verification.

Public publication is blocked by Critical release requirements that cannot be resolved without project-owner action or controlled CI evidence:

- Approved root license text is missing.
- Security disclosure channel approval is not recorded.
- Source-first package entries for Compiler, Runtime, and HTTP require explicit RC approval or a build-output packaging pass.
- Compiler, Runtime, and HTTP do not currently define clean package build scripts.

## Repository State

The root package remains private and acts only as the monorepo orchestrator. It owns verification, release validation, documentation, and CI wiring.

Current release commands:

- `bun run verify`
- `bun run benchmark`
- `bun run release:validate`
- `bun run release:validate:publication`

## Versioning Review

Versioning policy exists in [docs/VERSIONING.md](./docs/VERSIONING.md).

Current policy:

- synchronized RC package version: `0.1.0-rc.0`
- SemVer for public releases
- RC versions are allowed to change before stable release
- breaking changes require architecture and release-owner review

Stable cadence remains a future owner decision before `1.0.0`.

## Licensing Review

Package manifests declare `MIT`.

Critical blocker: root `LICENSE` is missing. No legal text was invented. Public publication must not proceed until the project owner adds approved license text or changes package license metadata.

Third-party dependency licensing appears minimal from current manifests:

- root dev dependency: `@types/bun`
- package dev dependency: TypeScript and Bun types
- production internal dependencies only among Warbler packages

Formal third-party notice requirements remain subject to license-owner review.

## Public API Review

Public API tests exist for Core, Compiler, Runtime, HTTP, and Playground boundaries.

Package exports are explicit. Internal subpaths are not package exports. HTTP now exposes `./package.json` intentionally for package metadata inspection.

## Build and Declaration Review

Core has build output under `dist` and publishes JS plus declarations.

Compiler, Runtime, and HTTP currently use source TypeScript runtime entry points and do not define package build scripts. TypeScript declaration output can be generated by `tsc`, but package manifests still use source-first entry points. This is a High RC limitation unless release owners approve source-first Bun package publication.

## External Consumer Validation

Permanent tooling exists at `scripts/release/publication-validation.ts`.

The validator creates package archives in a temporary directory and attempts a temporary external Bun consumer import through documented public entry points. The final release result remains blocked while Critical blockers are present.

## Package Archive Review

The publication validator inspects packed archives for:

- required package metadata
- README presence
- declaration presence
- executable source or JavaScript presence
- forbidden audit/test/security/benchmark content
- source map leakage
- secret-like file names

Archives must not publish tests, fuzz suites, benchmarks, internal audit reports, environment files, keys, or source maps.
